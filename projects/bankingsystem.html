🏦 Banking System

A fully object-oriented C++ console banking application featuring dual-role access (Banker & Customer), savings account management, transaction history, custom exception handling, and file-based data persistence.

Project Overview

The BMK Banking System is a modular C++ project that simulates core banking operations through a clean layered architecture. Roles are separated into Banker and Customer, each with their own UI class derived from a shared abstract UI base. Accounts are polymorphic — a SavingsAccount extends the abstract Account class, supporting deposits, withdrawals, and interest rates. All data can be persisted to file using structured I/O, and runtime errors are managed through a custom exception hierarchy.

Role-Based Operations

The system supports two login roles — Banker and Customer — each with a dedicated UI and a separate set of operations.

Banker

  • Authenticate with Banker ID & password
  • Create new customer accounts
  • View all registered customers
  • Link accounts to customers
  • Persist customer data to file

Customer

  • Authenticate with Customer ID & password
  • View personal account info
  • Deposit funds into savings account
  • Withdraw funds (with balance check)
  • View full transaction history

Core Features

Savings Account

SavingsAccount extends the abstract Account class with deposit, withdrawal, and configurable interest rate support.

Transaction History

Every deposit and withdrawal is logged as a Transaction object with type, amount, and date for a full audit trail.

Custom Exceptions

BankingException hierarchy provides meaningful error messages for authentication failures and insufficient funds.

File Persistence

Customer and account data can be saved to and loaded from files using structured ofstream I/O operations.

Smart Pointers

Uses shared_ptr throughout for safe, automatic memory management of Customers, Bankers, and Accounts.

Abstract UI Layer

Both BankerUI and CustomerUI inherit from a common UI interface, enforcing displayMenu() and handleOperations().

Key Challenges & Solutions

Polymorphic Accounts

Designed an abstract Account base class so new account types (current, fixed deposit) can be added without changing existing code.

Exception Safety

Built a custom exception hierarchy so all banking errors — from bad logins to overdrafts — are handled uniformly and descriptively.

UI Separation

Abstracted the UI layer behind a common interface, keeping business logic and display logic cleanly decoupled across roles.
